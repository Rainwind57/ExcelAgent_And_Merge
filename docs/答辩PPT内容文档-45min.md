## 2.2 engine/ —— Merge 引擎（9 min）

### 第 7 页：compare.py —— 语义判等 diff（解决 Q1）

**功能**：把"两分支 + 基准"三方逐格比对，输出"哪些格改了、哪些格冲突、哪些行漏了"。一句话：让 `"100"` 和 `100` 不再误报冲突。

**实现方案**（核心思路，三步）：

```
① 按第一列主键对齐所有版本的行 → 分出 matched / inserted / deleted / missing_row
② 逐格比：把每个值先归一成「语义键」再比 → 消掉"表示差异"造成的假冲突
③ 按三方关系归类：都没变=一致；只有一方变=changed；多方变不同=conflict
```

**数据结构**（关键字段）：

| 结构 | 字段 | 含义 |
|---|---|---|
| 语义键 | `('none'/'bool'/'num'/'str', v)` | 值归一后的判等尺 |
| 单元格 | `conflict / changed / diff_type` | 冲突标记 + 类型 |
| 行 | `row_type` | matched/inserted/deleted/missing_row |

**设计要点**：归一化**只判等不改值**——落盘保留原始类型；bool 单独归一避免 `True==1` 误判。

**讲法**（2 min）：先讲功能（消假冲突），再讲三步思路，最后点语义键数据结构。代码不贴，需要时翻附录。

---

### 第 8 页：compare.py —— 漏行检测（解决 Q1）

**功能**：合并前发现"基准有、但某个全量覆盖分支整行漏拷"的行，防止数据静默消失。

**实现方案**：

```
遍历主键：基准有、所有衍生分支都没有
  → 若该分支是全量覆盖类型（testbranch/trialbranch）→ 判定 missing_row
  → 输出告警，而不是默默删掉
```

**数据结构**：`SheetDiff.missing_rows` 列表，逐行记录漏掉的主键和来源分支。

**讲法**（0.5 min）：Q1 的第二层——漏行不是"删除"，是"漏了要报警"。

---

### 第 9 页：id_resolver.py —— ID 重映射（解决 Q2）

**功能**：多个分支各自新增了相同主键的行，合并时自动给后来者分配新 ID，并记录映射关系。

**实现方案**：

```
① 收集所有新增行的主键 → 按文件分组找"同主键多来源"
② 按文件优先级排序，先到者保留原 ID，后来者从 max(已用)+1 起重新分配
③ 重映射记录带「分支标记」(file, old_pk) → new_pk，供外键同步使用
```

**数据结构**：`id_mapping: [{file, old_pk, new_pk, reason}]`

**设计要点**：为什么带 `file` 分支标记？不同分支可能同旧主键，裸 `old_pk→new_pk` 会误命中别家的行——分支标记是正确性关键。

**讲法**（1 min）：Q2 的答案——撞车自动重映射 + 分支标记防误伤。

---

### 第 10 页：ref_integrity.py —— 引用完整性（解决 Q2）

**功能**：重映射后，把引用了旧 ID 的外键值跟着改成新 ID，再扫一遍检测"悬空引用"（引用了不存在的 ID）。

**实现方案**：

```
① 消费 id_mapping：凡外键值命中 (file, old_pk)，同步替换成 new_pk
② 全表扫描：外键值既不在本表主键集、也不在跨表主键集 → 标记 dangling（悬空）
```

**数据结构**：`remap_lookup: {(file, old_pk): new_pk}` 查表 + `dangling_refs` 告警列表。

**讲法**（0.5 min）：Q2 的第二道保障——重映射后外键跟着改，改完还能验悬空。

---

### 第 11 页：merge_engine.py —— 列策略自动合并

**功能**：不同列用不同合并规则自动合，减少人工裁决量。比如 ID 列保留基准、数值列取最大。

**实现方案**：

```
策略按「表 → sheet → 列」三级匹配，支持 * 通配：
  base_priority（ID/外键留基准）
  take_newer（取最新非空）
  take_longest（取最长文本）
  take_max（取最大数值）
  range_check（范围校验）
  manual（默认，留人工）
```

**数据结构**：`merge_strategies.yaml` 声明式配置，mtime 感知热更新，改策略不改代码。

**兜底**：自动合并后仍查列类型约束，类型不符降级人工。

**讲法**（1 min）：声明式策略 + 三级匹配 + 类型兜底。

---

### 第 12 页：fast_apply.py —— 大表快路径（解决 Q3）

**功能**：10w 行大表"只改十几格"时，不整表重写，直接改底层 XML，秒级完成。

**实现方案**：

```
① 资格判定：纯数据大表（无公式/批注/合并单元格）才走快路径，否则回退 openpyxl
② 定位行：建主键索引，找到要改的几行
③ 只重建目标单元格 XML（保留样式），文本用 inlineStr 不碰共享字符串
④ 有插删行时整表行号重排保证连续；仅末尾追加则 O(1) 免重排
```

**规模分层**：<512KB 走 openpyxl；512KB-10w 行向量化 compare；10w+ 纯数据走快路径。

**讲法**（1 min）：快路径只在纯数据大表启用，编辑语义严格对齐 openpyxl。

---

### 第 13 页：column_lineage.py + 公式缓存保护（解决 Q1/Q3）

**功能**：trunk 加列后，提前查出各分支缺了哪些列；以及保护公式缓存不丢。

| 能力 | 做什么 | 解决 |
|---|---|---|
| 列血缘 | 扫多分支，建 `{表→sheet→列: 空/有}`，输出缺列清单 | Q1 结构漏同步 |
| 公式列判定 | 公式文本一致→formula；引用值变→formula_changed；不一致→conflict | Q1 公式引用 |
| 公式缓存保护 | save 前后快照对比，缓存丢失就 LibreOffice 重算 | **Q3** |
| 批注三方 diff | 各版本批注不同 → comment_conflict | Q1 批注 |

**讲法**（1 min）：openpyxl 不处理的富结构，engine 层补了。

## 2.3 agent/excel/ —— Agent 引擎（11.5 min）

### 第 14 页：locator/ —— 表/列定位（解决 Q4）

**功能**：听懂策划说的"灵兽/宠物"指的是哪张表、哪个 sheet、哪一列。

**实现方案**（四层递进）：

```
L1 注册中心：60+ 表建索引，MD5 增量刷新，文件改动自动重扫
L2 模糊匹配：子串(0.5) + 编辑距离(0.35) + 字符重叠(0.15) 加权打分
L3 表格定位：7 路递进（精确名→别名→模糊→sheet→列→余弦→BM25）
L4 上下文：把定位结果注入 LLM prompt
```

**数据结构**：

| 结构 | 说明 |
|---|---|
| `TableMeta → SheetMeta` | 表元信息 + sheet 元信息（表头/行数/样本） |
| `row_index` | 行级倒排：`{列名: {值: [行号]}}`，加速主键查找 |

**关键设计**：歧义消解——多个候选置信度接近时（差 <0.05）交上层确认，不自动猜。

**讲法**（2 min）：Q4 第一层——"听懂策划在说哪张表"。

---

### 第 15 页：parser/ —— 意图解析（解决 Q4 多意图、跨表外键）

**功能**：把一句话拆成若干条结构化"意图"，并标出意图之间的外键依赖。

**实现方案**：

```
① 多意图拆分：一条长句 → 多条意图（每张表一条）
② 跨表外键：上游产出新 ID 打「produces 标签」，下游引用「consumes 标签」
③ 执行时按依赖拓扑序，把上游真实 ID 回填到下游占位符
```

**数据结构**（核心字段）：

| 字段 | 含义 |
|---|---|
| `action` | set / add / delete / get / col |
| `locator_fields/values` | 复合主键定位 |
| `extras["fields"]` | 列名 → 值 的写盘字典 |
| `produces_label` / `consumes_labels` | 外键依赖的标签链 |

**讲法**（1.5 min）：Q4 的载体——一个数据结构贯穿四步，跨表外键靠 produces/consumes 标签链。

---

### 第 16 页：subagent/ —— 拆分与校验（解决 Q4 拆分准确）

**功能**：拆分靠真实表结构而非死模板；执行前先校验意图对不对。

**实现方案**（两层校验）：

```
字段层（零 LLM，6 项检查）：列存在 / 类型 / 必填 / 唯一 / 枚举 / 范围
FK 拓扑层：按依赖顺序，检查「引用了还没产出的标签」→ 前向引用断裂
```

**关键设计**：校验**非阻断**——硬错误（类型不符/主键缺失）反问用户修正；软警告（列不存在/引用断裂）放行，交写盘兜底。

**讲法**（1.5 min）：Q4 第二层——拆分靠真实 schema，校验两层拦截。

---

### 第 17 页：pipeline/ —— 4-Step 流水线（解决 Q4 整体编排）★

**功能**：把"自然语言"变成四步确定性流水线，替代老架构"先拆后定位"的混乱。

**实现方案**（从失败到反转）：

```
老：先拆后定位 → 拆分器不知道真实列定义 → "封印魔龙" 10min/23次LLM 只写 2 表
新：先定位按列拆 → schema 驱动
  Step1 ParseAgent     定位 → 拉真实列约束 → 按列拆分
  Step2 ValidateAgent  两层校验
  Step3 ExecuteAgent   拓扑排序 → 零 LLM 原子写盘
  Step4 ConcludeAgent  汇总 + 失败清单 + 自学习
```

**关键设计 —— LLM 预算分层**：LLM 只进 Step1（拆解）和 Step4（总结）；Step3 执行零 LLM。理由：LLM 进执行循环 = 延迟加回来 + 引入不确定性。

**数据结构**：`StepContext` 承载四步产物流转（`artifacts["intents"/"validated"/"failures"]`）。

**讲法**（2.5 min）：Q4 的核心，全篇技术主线——先讲失败故事，再讲反转。

---

### 第 18 页：core/ —— 安全与编排（解决 Q5）

**功能**：保证 AI 写不坏数据——写前可回滚、写后能校验。

**实现方案**（五层防线）：

```
① 写前备份 + JSONL 审计 + 按索引回滚
② dry_run 预览 diff，确认才写盘
③ 语义闸门 + 置信度，低置信不自动执行
④ 公式缓存保护
⑤ 写后校验（主键唯一 + 引用完整 + 列类型）
```

**数据结构**：备份索引（可回滚的版本号）+ 审计日志（JSONL 逐条）。

**讲法**（2 min）：Q5 的完整答案——core 目录 = 安全 + 编排 + 上下文。

---

### 第 19 页：repair/ —— 写后修复（解决 Q5 写坏能修）

**功能**：写盘后发现错误，自动按错误类型定向修复，最多 3 轮，修不动再升级或问人。

**实现方案**：

```
① 写盘后验证 → 发现错误 → 分类（9 类错误）
② 按错误类型选修复策略：重执行 / 升级 LLM / 中止
③ 重复策略则停止，避免死循环
④ 语义类错误（如"这值不对劲"）直接反问用户，不浪费 LLM
```

**数据结构**：9 类错误枚举（列不存在/行不存在/类型不符/ID冲突/主键错位/跨表断裂/公式错误/语义异常/未知）。

**讲法**（1.5 min）：Q5 最后一环——写后 3 轮自适应修复 + 定向回退。

### 第 20 页：skills/ —— 表结构知识底座（解决 Q4）

# 附录 B：Q&A 预演清单

1. **为什么不用 git merge / pandas diff？** —— Excel 富结构，git 无单元格粒度，pandas 无公式/批注语义。
2. **语义归一会不会误判？** —— 只判等不改值；bool 单独归一；`value_constraints.yaml` 兜底。
3. **merge-base 怎么定？** —— `svn log --stop-on-copy` 反查 copyfrom-rev；三级降级。
4. **LLM 上下文怎么不超限？** —— Token 感知增量加载 + 12000 上限 + 2000 余量。
5. **AI 挂了系统能用吗？** —— 规则短路 / 零-LLM fallback / Merge 全链路零 LLM / 熔断。
6. **怎么保证不写坏数据？** —— 五层防线 + 两层校验 + 写后修复。
7. **性能数据可复现吗？** —— 压测资产幂等生成 + bench 脚本 git stash 对照。
8. **测试怎么不 flaky？** —— 缓存隔离 / 快照基线 / sys.path 收口 / 零-LLM 优先。
9. **反模式归纳会学错吗？** —— pending 隔离 / promote 守卫 / 生产默认不归纳。
10. **为什么不用数据库？** —— 策划交付物就是 Excel；SVN 版本管理天然是文件。
11. **为什么主链路不用 ReAct？** —— 配表确定性任务，ReAct 不可控；仅失败修复 L2 用。
12. **为什么自研 orchestrator 不用 LangGraph 图？** —— 4-Step 需 StepContext 产物流转 + 硬/软错误分级。
